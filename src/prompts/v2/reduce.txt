You are synthesising the final structured extraction from many chunk-level extractions of a single video. This output is consumed by a downstream agent that scores it against a goals file and proposes actions. Optimise for the agent: preserve mechanisms, attach timestamps, dedupe across chunks.

# Input

Video title: {title}
Channel: {channel}
Duration: {duration}
URL: {url}

Chunk-level extractions (one JSON object per chunk, in order):
{chunk_extractions}

Transcript (with line-mapped timestamps where available):
{transcript_with_timestamps}

# Task

Produce a single JSON object matching the schema below. STRICT JSON, no commentary, no markdown fences.

# Output schema

{{
  "meta": {{

    "channel": "{channel}",

  "transferable_atoms": [

# Atom rules

- Atoms are the priority output. Aim for 3-8 atoms per video. If a video has no reusable mechanisms, return an empty list — do NOT manufacture atoms from vague advice.
- Each atom must be referenceable: an agent picking it should know exactly what to look up in the transcript. If the mechanism can't be stated concretely with specifics, drop the atom.
- IDs: atom_01, atom_02, atom_03, etc.
- Type vocabulary (closed set): implementation_pattern, framework, org_pattern, business_model, revenue_pattern, architecture, tool_recipe, concept
- Evidence vocabulary (closed set): stated_practice (speaker says they do it), framework_claim (speaker defines a taxonomy), anecdotal (one-off example), data (cited numbers)
- Deduplicate across chunks. If chunk 2 and chunk 5 both surface the same atom, keep one with the merged timestamp range.
- Dependencies: list of strings naming concepts/tools the atom relies on. Empty list if none.
- timestamp: "MM:SS-MM:SS" using zero-padded MM and SS. Round down to whole seconds. Use chunk-level data to fill in ranges when possible; otherwise use the timestamp of the most specific claim/concept the atom came from.

# Stack rules

- Only name tools/systems the speaker actually mentions. No invented integrations.
- "role" should describe how the tool was used in the speaker's setup, not a generic description. Example: "human-agent interface via 'Loop Alley' Slack channel" not "team chat".

# Open questions rules

- Things a thoughtful viewer would want to follow up on. NOT trivia. NOT things the speaker already answered.
- 1-5 questions. Empty list if nothing worth flagging.

# General rules

- Be precise. Don't editorialize. Don't invent. Drop vague takeaways — only concrete ones.
- Deduplicate concepts/claims across chunks: a concept introduced in chunk 2 and referenced in chunk 5 should appear once, with timestamp from chunk 2.
- Length budget for `markdown`: readable in 60 seconds. Tight.
