You are extracting structured information from a single chunk of a video transcript. The chunk is part "{part_label}" of {total_chunks}.

# Input

Video title: {title}
Channel: {channel}
Chunk timestamp range: {start_ts} -> {end_ts}

Transcript chunk:
```
{transcript}
```

# Task

Extract every piece of structured information present in this chunk. Be precise — only extract what the speaker actually said in this chunk. If a category is empty, return an empty list.

# Output schema

Return strict JSON, no commentary, no markdown fences. The response MUST parse with json.loads:

{{
  "claims": [
    {{"text": "specific factual assertion as stated", "timestamp_seconds": 12.4, "verifiable": true}}
  ],
  "concepts": [
    {{"name": "Concept Name", "definition": "one-line definition drawn from how the speaker uses it", "first_timestamp_seconds": 30.1}}
  ],
  "examples": [
    {{"summary": "what the example illustrates", "timestamp_seconds": 45.0}}
  ],
  "actions": [
    {{"text": "imperative statement of what to do", "timestamp_seconds": 60.2}}
  ],
  "entities": [
    {{"name": "person/company/tool/paper name", "type": "person|company|tool|paper|other", "first_timestamp_seconds": 75.0}}
  ],
  "atoms_precursors": [
    {{
      "label": "short noun phrase, 2-5 words, that names a reusable mechanism (not a vague takeaway)",
      "type": "implementation_pattern|framework|org_pattern|business_model|revenue_pattern|architecture|tool_recipe|concept",
      "evidence": "stated_practice|framework_claim|anecdotal|data",
      "mechanism": "the actual reusable mechanism, preserving specifics. NOT a paraphrase. If you cannot state it concretely, drop it.",
      "dependencies": ["prerequisite concept or tool the mechanism relies on, if any"],
      "timestamp_seconds": 90.0,
      "timestamp_end_seconds": 110.0
    }}
  ]
}}

# Rules

- "claims" are statements the speaker asserts as fact. Set "verifiable": true if a human could check it against a public source; false if it's opinion, preference, or personal experience.
- "concepts" are named ideas the speaker introduces or explains.
- "examples" are concrete cases the speaker gives to illustrate something.
- "actions" are anything phrased as advice or instructions to the listener.
- "entities" are proper nouns: people, companies, tools, papers, products.
- "atoms_precursors" is the most important category. Each entry is a discrete, referenceable unit the downstream agent will score against a goals file. Be SELECTIVE — prefer 3 sharp atoms over 10 vague ones. Drop anything where the mechanism is paraphrased into "look for X" or "consider Y". If the speaker says "I do X" or "the trick is to X", capture the EXACT mechanism with specifics preserved.
- timestamp_seconds / timestamp_end_seconds: integers in seconds, both inside the chunk's range. timestamp_end_seconds can equal timestamp_seconds if the atom is a single sentence.
- Maximum 15 items per category per chunk. Prioritise the most important.
- Do NOT invent timestamps outside the chunk range.
